# SDS Dev Governance Version

Version: `v1.29.0`

Date: `2026-09-19`

Highlights:

- New resource category `resources/web-components/`: complete validated components promoted from real
  projects (working source + validated site-side integration + agent procedure). First leaf `tree-3d`: a
  procedural animated Three.js tree with a React wrapper, a framework-free `mountTree` and a no-build HTML
  demo. `knowledge/` is now published, and the Android/Google Play release guide moved from
  `resources/how-to/` to `knowledge/android/how-to-release-an-app/`. Checker fix: routing references no longer
  fail by SIGPIPE on large copies.

- pstack skills integrated declaratively: one lazy node `skills/pstack.md` and one router row select
  `how`/`architect`/`blast-radius`/`interrogate`/verification/`tdd`/TypeScript per task, phase and
  risk; «sin pstack» exclusion inherited by subagents and continuations; no installer, bridge or
  vendored copy; always-read set stays under budget.

- Optional MCP inventory/check/doctor, protected configuration staging and closed Hostinger
  gateways. Synthetic custody/batch controls are tested; live access remains explicitly
  blocked until independent isolation and authenticated human channels are verified.

- Optional bounded section reader, explicit dependency closure and read-only revision freshness.
  Measurement includes fixed context and complete retrieval overhead; no universal 75% claim.

- Repair release: bounded files-only/hub bootstrap, conservative copy classification and preserved
  Upnews SwiftUI resource. See REL-2026-09-09-10 evidence and changelog.

- Canonical reconciliation: the validated downstream `v1.24.1` lineage promoted upstream, with the
  Vercel skill, the `sds-r8-analyzer` bundle, the Android/Google Play release knowledge and a
  parallel `v1.23.0` frontend lineage preserved rather than dropped.
- Permanent promotion and distribution contract in `practices/modules/11-governance-distribution.md`
  plus `scripts/governance-copies.sh`, which classifies `0..N` discovered governance copies against
  a baseline without naming any project.
- Minimum sufficient subgraph: total governance knowledge may grow while a task loads only the
  mandatory static set, the index entries it selects, the nodes those name and their dependencies.
- Stable semantic skill slugs; ordering belongs to generated indexes, never to filename identity.
- One owner per catalog fact: installation, propagation and observed reachability are separate files
  and none restates another.
- Routing is validated, not assumed: existence, integrity, coverage and task-level selectivity are
  checker gates, and the generated skill index is compared against the policy it derives from.
- Concurrent-writer discipline: isolated branch and worktree, path-scoped staging and staged-diff
  inspection before every commit.
- Neutral `GOVERNANCE.md` entry point.
- Multi-agent adapters for Claude, Codex, Gemini, and Cursor.
- Selective governance runtime: compact kernel + semantic practice INDEX + routed detailed
  practices, preserving the full rule corpus while reducing the always-read SDS set by 81.2%.
- Declarative skill catalog installed/checked by default, with explicit opt-out and fail-closed
  separation between availability and capability admission.
- Pinned Three.js skill package materialized for Claude and shared with Codex without overwriting
  existing skill destinations.
- Lazy base-plugin catalog with bounded gitignored runtime tracking and an idempotent official
  Figma Design/Make setup for Claude Code and Codex; OAuth remains explicit and fail-closed.
- Bootstrap equivalence between `init.sh` and `init-project-prompt.md`.
- Portable adapter placeholders and a checker gate against source-project names or machine paths.
- Non-destructive bootstrap for existing projects.
- Nested adapters for context compartmentalization.
- Prompt deltas, discovery before hardcoding, cross-layer contract lineage, mutation resilience,
  and secure degraded-operation rules.
- Frontend constants, business-info, i18n, and user-facing assets/photos portability rule.
- Phase close discipline: implementation commit/checkpoint series + risk report per implementation
  phase, conditionally loaded.
- Prompt naming uses executed iterations plus pre-execution suffixes (`-alpha`, `-beta`, ...).
- Optional frontend pattern resources are available under
  `sds-dev-governance/resources/frontend-patterns/` and are loaded only on explicit request.
- `procedural-horizon-hero`, `grounded-editorial-studio` and the neutral runnable
  `grounded-studio-reference` preserve the current owned studio-site grammar as reproducible,
  config-driven clean-room knowledge. Their empirical gate rebuilds a neutral hero and continuation
  without source/assets/screenshots and treats every guess as a pattern defect.
- The `expandable-search-filter-panel` resource preserves the collapsible panel, expanding search,
  aligned progressive filters, shared filter state and accessible/reduced-motion behavior; both
  bootstrap paths and the checker require its complete portable leaf.
- The `notification-toast-stack` resource (`notificaciones-01`) preserves dependency-free,
  accessible `info`/`success`/`error` feedback with safe DOM copy, a 3.5-second default, immediate
  activation dismissal, responsive layout and reduced-motion behavior.
- New project bootstrap creates empty legal/policy placeholders under
  `docs/<project-name>-policies/`.
- Graphify installer and skill guidance: bootstrap registers project-scoped adapters for Claude
  Code, Codex, Gemini, and Cursor by default.
- Memory tree: thematic areas may shard into `index-<area>.md` (entrypoint) + `<area>-N.md` shards
  loaded on demand; direct maps reject missing/duplicate/subshard/cyclic routes; a flat `<area>.md`
  remains valid only before migration and becomes a deprecated stub afterward. Graphify is auxiliary
  discovery, not a primary load.
- Non-executable prompt preface (`PREFACE — NON-EXECUTABLE`) standardized for `LEVEL 2-3` prompts, with
  template and examples.
- Read-only prompt preflight template for high-risk pre-execution review, adapter trigger aliases
  for Claude/Codex/Gemini, plus detailed governance change log required for governance updates.
- Contract authority and contradiction gate with a lightweight static router and conditionally
  loaded practice: semantic evidence roles, owner `stop-and-ask`, explicit resolution classes, and
  no automatic precedence for repository/runtime over authorized normative intent.
- Agentic-engineering module: AI-code assurance (The Golden Rule — a PR signature is 100% ownership,
  human- or AI-drafted — plus the improved assurance checklist), GitHub/GitLab PR/MR templates with a
  machine-checkable footer, and a posterior `check-ai-pr-assurance.sh` validator. Conditionally
  loaded at PR/MR preparation for executable changes (not static context).
- Agent-capability admission gate: six property-based gates, light/full routes and delta
  reassessment in lazy-loaded `practices/modules/11-capability-admission.md`; routine exact-match
  invocation uses the always-read skills router plus the project effective-revision ledger.
- Incremental governance synchronization: canonical-owner reuse plus an updated RULE-COVERAGE
  impact index; Graphify is an optional derived candidate view, never authority or a second index.
- GitHub remote-deletion guardrails: non-delegable manual-owner deletion/protection rule,
  fail-closed `gh` allowlist, exact-ref safe push, per-clone pre-push hook, canonical bypass-free
  branch ruleset, idempotent audit/apply and negative tests. Unsupported plans remain visibly red.
- Routing evaluation distinguishes Git path area proxies from audited required shards, publishes
  blindness/ambiguity, and never declares `ROUTING_PROVEN` from non-blinded evidence.
